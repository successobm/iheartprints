## Concept Generation & Asset Storage (Production Safety)

Real (OpenAI) concept generation must stay **disabled** by default. The current
safe environment configuration is:

```
CONCEPT_GENERATION_PROVIDER=placeholder
ASSET_STORAGE_MODE=data_uri
CONCEPT_GENERATION_ENABLE_REAL=false
```

`data_uri` embeds generated bytes in database rows / JSON records. That is
acceptable for local development, automated tests, placeholder concepts, and
architecture verification — it is **not** acceptable for real production
images (row/API/snapshot/backup/memory inflation).

`ASSET_STORAGE_MODE=supabase_storage` is implemented (private `design-assets`
bucket via the service role and signed URLs). `s3` remains reserved and
unimplemented. Even with Supabase Storage available, real generation must
remain off until production configuration, migration/bucket setup, worker
scheduling, and controlled live verification are complete.

The app enforces this in configuration and composition
(`src/lib/config/generation-provider-config.ts`,
`src/lib/config/asset-storage-config.ts`,
`src/capabilities/providers/resolve-concept-provider.ts`):

- `CONCEPT_GENERATION_ENABLE_REAL` defaults to false and blocks the OpenAI
  adapter until explicitly set to `true`.
- In production, `CONCEPT_GENERATION_PROVIDER=openai` without a production-safe
  `ASSET_STORAGE_MODE` does not silently fall back to placeholder concepts —
  generation reports itself unavailable with a safe, non-secret error code,
  before any provider request or concept/asset persist.

Enabling real generation in production requires **all** of:

1. `CONCEPT_GENERATION_PROVIDER=openai` + `OPENAI_API_KEY`
2. production-safe `ASSET_STORAGE_MODE=supabase_storage` (or a future `s3`
   adapter)
3. `CONCEPT_GENERATION_ENABLE_REAL=true`
4. a configured independent worker (`WORKER_SECRET` + scheduled invocation or
   `npm run worker`)

OpenAI generation is not active under the safe defaults above. See
`.env.example` and [ARCHITECTURE.md](./ARCHITECTURE.md) §21. Never commit a
real API key.
